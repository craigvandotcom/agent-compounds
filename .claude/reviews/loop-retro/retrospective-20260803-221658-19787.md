# Retrospective — run-2 five-batch (RUN_ID 20260803-221658-19787)

Scope: cross-batch patterns, bead-spec quality signals, and workflow-file gaps not
already captured by the per-stage friction carrier (~40 items, tiered separately).

## What Worked

- **execute-at-draft held the line.** Every one of the 6 refine lanes (A–F) caught AC
  commands that were non-biting, self-terminating, or miscounted BEFORE they reached an
  implementer (RefineC round 1: insertion probes tripping the wrong check, an awk range
  self-terminating on its own header, a grep off-by-one; RefineA/D/E similar). No batch
  progress.md records an implementer hitting a dead AC — the gate is earning its keep.
- **Adversarial re-verification consistently held findings to account.** RefineB round 2
  independently re-executed all 12 round-1 pasted outputs and reproduced them exactly;
  RefineF round 3's corpus specialist built a simulated section and ran the new ACs
  against it live. Round floors (MIN_ROUNDS=3) repeatedly surfaced real Critical/High
  findings in round 3 that a 1-round pass would have missed (RefineB round 4 Critical,
  RefineE round 3 findings on ac-kqpw.8).
- **Batch-close's combined review caught two real cross-file consumption bugs this run
  produced** (`BATCH_RANGE` / `DIFF_PATHSPEC` not surviving across fenced bash blocks —
  the same class of bug ac-ewgr.2's TARGET_BEADS fix addressed one layer down), and the
  provenance-strip auto-fix held the batch to the bar its own `f519f3e` commit set.
- **De-parenting `ac-kqpw.8` from containment to `discovered-from`** (RefineF) shows the
  parent/provenance distinction from bead-conventions is being applied correctly under
  pressure, not just stated.

## What Didn't Work

- **Bead specs entering refine carried systematically wrong repro/measurement data.**
  Round 1 of every one of the 6 refine lanes found Critical/High "premise failures" —
  wrong line numbers (ac-sm6w 544-545 → actually 584; ac-ewgr.3 "all four repro numbers
  wrong"), stale/impossible repro (ac-ewgr.2's `--beads-rescue` claim falsified,
  ac-ewgr.4 unsatisfiable without `severity:medium`), and measurements off by ~2x
  (ac-wrsb.2 fork/timing) or wrong units entirely (ac-36wi: claimed 12:30 wall-clock,
  re-measured 567s, exit 1 not 0). This was consistently each lane's single largest round
  (13–15 findings in round 1 vs 1–7 in rounds 2+) — a real, recurring first-round tax
  paid on every batch. Root cause is diffuse (some via `ac-land`'s fast T1 filing from a
  prior session's friction narrative with no execute-before-file gate, some via natural
  code drift between finding-time and refine-time) — no single fixable file, so this is
  recorded as a pattern, not pushed into a proposal below.
- **The `net-growth-ok` stamp's correct form is context-dependent and undocumented at the
  rule's definition site.** RefineB round 4 found a Critical: round-3's lint-gate ACs
  prescribed the HTML `<!-- net-growth-ok: … -->` form for stamps landing INSIDE a
  ```bash fence (SKILL.md:543-627 in ac-batch-close), where an HTML comment is a bash
  **syntax error** (`bash -c '<!-- net-growth-ok: x -->\necho hi'` exits 2). Check 14's
  grep is comment-syntax-agnostic, so the break would have been invisible to the gate —
  each of the three affected beads' own replay ACs would have failed on a syntax error
  masquerading as a correct implementation. See System Upgrade Opportunities #1.
- **A finding filed on the wrong repo's board needed ad hoc handling twice.** `ac-36wi`
  lives on the agent-compounds bead board but its actual fix (hot-lane-lint timeout,
  `weekly.json`) lives in the sibling ROOT repo. RefineC flagged this in round 2 as
  unresolved ("Open follow-up for the conductor: ac-36wi is misfiled") and it still
  shipped with a bespoke commit-hash-from-another-repo entry in `wrsb.1`'s progress.md
  and a custom "routing flag recorded in the close reason" carve-out at batch-close. No
  canonical process exists for this — see System Upgrade Opportunities #2.
- **The same ~150-line trigger-corpus duplication was flagged and deferred twice**
  (RefineE: "boilerplate duplication (High, single agent) — see registry"; RefineF:
  "same disposition as the .1-.4 refine — surfaced to conductor"). Re-litigating and
  re-deferring the identical structural finding across two independent refine lanes is a
  real (if small) recurring cost, but there's no single obvious template file to target a
  fix at from the artifacts alone — flagged here, not proposed.

## Patterns Observed

- Round-1 finding volume (13–15 Critical/High-heavy) vs round-3+ (0–3, mostly Medium) was
  consistent across all 6 lanes regardless of batch content (bug fixes vs trigger-copy
  passes) — the convergence curve is a property of the refine loop, not the bead type.
- Every refine lane that touched a `bug`/`decision`-typed bead independently found and
  fixed the SAME class of defect ac-ewgr.2/.4 exist to fix in the pipeline itself
  (unverified premises, non-biting ACs) — the refine loop is, in effect, running the same
  quality gate on beads that the batch's own bug fixes were adding to the pipeline
  mechanically. Encouraging (the manual gate and the automated one agree) but also a
  signal that upstream filing quality is the actual lever, not refine's rigor.
- No batch's progress.md was a stub — all five batch dirs and six refine dirs had
  complete, substantive logs; no need to fall back to the review artifacts to reconstruct
  lane activity.

## System Upgrade Opportunities

### 1. Document the `net-growth-ok` stamp's syntax-context rule at its definition site

**Target:** `lint.sh` — the Check 14 block comment (lines 654–668) and/or the fail
message at line 791.
**Change:** Add one line: the stamp's grep target is the literal substring
`net-growth-ok:` on any added line — form is NOT fixed. Inside a fenced/executable
context (e.g. a ```bash block) it MUST be a `#`-prefixed comment (an HTML `<!--` there is
a shell syntax error); in prose it's the `<!-- net-growth-ok: … -->` HTML form. Point at
the existing precedent already in the tree (`ac-batch-close/SKILL.md:291,606,615,670,703`
use `#`; prose sites use HTML) so the rule is discoverable without re-deriving it.
**What it cost us:** RefineB spent Round 4 (of a 5-round refine) finding and fixing a
Critical defect where all three of that lane's beads' ACs prescribed the syntax-breaking
HTML form for stamps that land inside a bash fence — verified live (`bash -c '<!--
net-growth-ok: x -->\necho hi'` exits 2 vs `# net-growth-ok: x` exits 0). Had it shipped
unfixed, three beads' own replay tests would have broken on a syntax error a
comment-syntax-agnostic grep (Check 14) cannot detect — an invisible, self-inflicted
break in the exact machinery this run was hardening. Currently the only way to learn the
context-dependent form is to notice precedent by eye, which is exactly what round 4 had
to do the hard way.
**Evidence:** `/tmp/bead-refine-TopazHawkRefineB-54483-20260803-221658-19787/progress.md`
Round 4; `lint.sh:654-668,791`; `skills/ac-batch-close/SKILL.md:291,606,615,670,703`.

### 2. Give cross-repo-scoped beads a canonical routing/handling convention

**Target:** `skills/beads-standards/reference/bead-conventions.md`.
**Change:** Add a short section covering beads whose fix lives outside the repo the bead
board belongs to (agent-compounds board, ROOT-repo files, as happened this run) —

reasons) a standard "cross-repo: files live in `<repo>`" bead-description field and a
standard close-reason phrasing, so batch-close doesn't need to improvise a bespoke
carve-out each time.
**What it cost us:** `ac-36wi` needed ad hoc handling at two separate stages this run —
RefineC round 2 flagged it as an unresolved open item ("conductor/ac-tidy" follow-up,
never actually resolved by refine), and `wrsb.1`'s progress.md had to record a foreign

the close reason") that batch-close then had to carry through the ceremony. This is a
recurring risk, not a one-off: agent-compounds is shared tooling symlinked into every
sibling app and the ROOT repo, so findings that touch the deploy target rather than the
skill source will keep landing on the wrong board without a named convention.
**Evidence:** `/tmp/bead-work-ac-wrsb.1-20260803-20260803-221658-19787/progress.md`
bead `ac-36wi` entry; `/tmp/bead-refine-TopazHawkRefineC-96014-20260803-221658-19787/progress.md`
